# Protocol v1 control payloads

All multi-byte integers are little-endian. Reserved bytes/bits must be zero when sent and must be rejected when non-zero in protocol v1.

## HELLO — 32 bytes

| Offset | Size | Field |
|---:|---:|---|
| 0 | 16 | Persistent Device ID, opaque random bytes |
| 16 | 1 | Role: 1 Android controller, 2 Windows receiver |
| 17 | 1 | Transport mask: bit0 USB, bit1 Wi-Fi, bit2 Bluetooth |
| 18 | 4 | Capability flags |
| 22 | 1 | Minimum supported protocol major |
| 23 | 1 | Maximum supported protocol major |
| 24 | 1 | Maximum minor for the advertised maximum major |
| 25 | 1 | Trust state: 0 unpaired, 1 paired |
| 26 | 6 | Reserved |

Capability flags:

- bit0: rumble receive/support;
- bit1: Guide/Home support;
- bit2: 240 Hz competitive state rate;
- bit3: warm-standby transport;
- bits4..31 reserved.

HELLO may use a zero Session ID because a session may not yet exist.

## AUTH_CHALLENGE — 32 bytes

32 cryptographically random challenge bytes generated by the Windows receiver for a trusted reconnect.

A challenge must never be reused intentionally.

## AUTH_RESPONSE — 16 bytes

The first 16 bytes of the HMAC proof defined in `security.md`.

## SESSION_READY — 8 bytes

| Offset | Size | Field |
|---:|---:|---|
| 0 | 1 | Selected major |
| 1 | 1 | Selected minor |
| 2 | 1 | Current transport |
| 3 | 1 | Flags, reserved zero in v1 |
| 4 | 4 | Negotiated capability flags |

SESSION_READY uses a non-zero Session ID and an authenticated frame for paired sessions.

## HEARTBEAT / HEARTBEAT_ACK — 8 bytes

| Offset | Size | Field |
|---:|---:|---|
| 0 | 4 | Probe ID |
| 4 | 4 | Reserved |

The sender timestamp is already carried in the frame header. The ACK echoes the same Probe ID.

## TRANSPORT_READY — 4 bytes

| Offset | Size | Field |
|---:|---:|---|
| 0 | 1 | Transport |
| 1 | 3 | Reserved |

This indicates that the secondary transport is authenticated and may enter stabilization/candidate evaluation. It does not make the transport authoritative.

## HANDOVER_PREPARE — 8 bytes

| Offset | Size | Field |
|---:|---:|---|
| 0 | 1 | Candidate transport |
| 1 | 1 | Reason |
| 2 | 2 | Reserved |
| 4 | 4 | Expected next global realtime sequence |

Reason values:

1. preferred transport became ready;
2. active transport degraded;
3. active transport critical/lost;
4. explicit user override.

## HANDOVER_COMMIT — 8 bytes

| Offset | Size | Field |
|---:|---:|---|
| 0 | 1 | New authoritative transport |
| 1 | 3 | Reserved |
| 4 | 4 | First authoritative realtime sequence accepted on the new transport |

The receiver must atomically change authority only after it has validated the handover state.

## RUMBLE — 4 bytes

| Offset | Size | Field |
|---:|---:|---|
| 0 | 1 | Low-frequency motor intensity 0..255 |
| 1 | 1 | High-frequency motor intensity 0..255 |
| 2 | 2 | Suggested duration in milliseconds, 0 means implementation/default duration |

Rumble is output traffic and must never block realtime input processing.

## DISCONNECT — 4 bytes

| Offset | Size | Field |
|---:|---:|---|
| 0 | 1 | Reason |
| 1 | 3 | Reserved |

Reason values:

1. normal app shutdown;
2. user disconnect;
3. protocol/version failure;
4. authentication failure;
5. transport replaced;
6. fatal local error.

Unexpected transport loss is handled by timeout/recovery and does not require a DISCONNECT frame.
